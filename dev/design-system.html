EshaalTab Design System

Live page: every swatch and value below is read from css/tokens.css at load, so it can never drift from the product.

Creative north star: the personal instrument panel

The chassis is deliberately neutral so the user's own choices give each install its character. Structure — panels, layered elevation, one accent colour, a softly-cornered search pill — stays constant; wallpaper, accent colour and clock typeface change per user. The system's job is to stay legible and out of the way, the way an instrument panel's layout doesn't change even though the view out of the window does.

This is a power-user utility, not a mood board. Density and information access (Ctrl+K search, board cards, popovers) beat decorative flourish, and depth encodes real hierarchy rather than richness.

Key characteristics
  • One user-chosen accent colour, used sparingly, never as a background
  • Elevation tracks real stacking order: cards → dropdowns → modals → overlays
  • Blur only on surfaces that genuinely float over the wallpaper, never stacked
  • Two themes (dark default, light) sharing one token set
  • Every visual cue answers "what is this, and is it above or below me"

Colours

Near-monochrome at rest: one neutral surface family plus a single user-chosen accent. There is no secondary brand colour — the accent is the only colour decision an install makes. Toggle the theme above to check every swatch in both modes.

Surfaces

Text and borders

Board surfaces

Board cards tint themselves from --board-rgb and --board-opacity, so each board reads as its own place without a second brand colour. Text ink on a board is computed for contrast against the card's real backdrop, including the wallpaper behind a translucent card.

Status

The One Signal Rule. The accent appears on focus states, hover borders, primary actions and active toggles — never as a page background, a card fill or body text. More than one or two accent-coloured elements visible at once means something has drifted.

Scoped exceptions

Three surfaces are allowed to leave the token set. Each is documented, and the list is closed.

Command palette (light theme)

Cool-slate ink instead of the alpha-on-white neutrals, because the palette floats above an arbitrary page and needs colder, higher-contrast ink at small sizes: #0f172a titles, #475569 meta, #64748b dim, #cbd5e1 lines, #f1f5f9 hover.

Focus timer

A full-screen blackout that ignores theme and accent so a focus session looks identical everywhere: #000 ground, flip face #151618 with seam #292a2d / #25262a. Its corners are viewport-relative (1.2vw) and it uses sub---r-sm radii (2px, 7px) found nowhere else.

Toolbar popup

A fixed 320–360px shell, not a new-tab surface. Its outer corner is 12px, between --r-sm and --r-md, sized for the browser's popup frame. It mirrors the page tokens through its own theme function, including a readable accent ink so selected rows stay visible on white.

Typography

Interface: Inter, with system fallbacks. Users may switch the whole interface to one of eight bundled faces via --font-app. Clock: ten faces via --clock-font, the one typographic choice exposed to the user, scoped to the clock. Mono: --font-mono for keyboard chips and literal input only. All bundled fonts are SIL Open Font License, except Roboto Slab (Apache 2.0).

Outside the ramp

  • Clock — --clock-size, viewport-relative and scaled by the user's clock-size slider.
  • Countdown — the focus timer's flip clock, sized against the viewport so it reads across a room.
  • Micro (10–11px) — compact popover hints and the toolbar popup only, never on the main page.
No near-duplicate steps. Don't let 2–3 font sizes cluster within a few pixels on one surface. Pick fewer steps with real contrast (≥1.25×).

Shape & spacing

Four radius steps, no sharp corners. Borders are hairline (--hair) and low-contrast at rest, strengthening only on hover, focus or accent states.

Spacing scale

UI chrome (buttons, pills, tight lists) sits in the 4–16px range; section-level gaps use 20px and above. Spacing and type scale together through --ui-scale.

Elevation

Structural, not decorative. Shadows are built from a shared accent-tinted --shadow-tint with a tight contact shadow plus a soft ambient one, so depth reads as the same light source everywhere. Settings uses flat fills and borders instead.

The Stack-Tells-The-Truth Rule. A component's shadow step must match its real interaction layer. Don't reach for --e4 on a resting card to make it pop; that breaks the cue everywhere else.

Wallpaper legibility

Text sitting directly on a photo or video uses a text-shadow driven by --wp-shadow-opacity, --wp-shadow-blur and --wp-shadow-rgb. It is functional, and off in solid-colour mode.

Motion & layering

Duration and easing

One easing curve for everything that enters or settles. Page switches fade a pre-blurred wallpaper layer with opacity instead of re-blurring the image, so a switch stays cheap on large screens.

Z-index scale

Layout

A single-page shell: fixed top bar, centred clock and search pill, a board-card grid, and side sheets that overlay rather than push content. There are no marketing-style breakpoints. Instead --ui-scale steps 1 → 1.12 → 1.3 → 1.55 → 1.8 at 1800px, 2200px, 2800px and 3400px, multiplying spacing and type together so dense information stays proportional on very large displays.

Board columns and gutters derive from one gutter token so margins stay equal on every screen size. The toolbar popup is a separate, simpler register: a fixed-width single-column stack with no side sheets.

Components

Buttons

--r-sm corners, pill only for compact presets. Primary is an accent fill with accent-contrast text, a neutral elevation shadow, and no gradient or coloured glow. focus-visible always draws a 2px accent outline at 2px offset — the one hard accessibility invariant, set globally in tokens.css.

Search pill

Search or type a URL

--r-md at 40px tall on --surface-search, deliberately narrower than a full-width bar so the eye reaches the clock first. Its border promotes to the accent on hover or focus — the main place the accent does structural work.

--r-lg corners, e1 at rest promoting on hover, border from the board's own tint rather than the global accent. Title and tile ink are computed against the real backdrop (card colour, its opacity, and the wallpaper behind it), so lowering the background strength never strands unreadable text.

Inputs

--surface-panel-2 fill, soft border, corners a step tighter than buttons so nested fields read as content rather than chrome. Focus uses the same 2px accent outline as buttons — one focus treatment system-wide, never a glow or a scale change. Placeholders always use --text-dim at full opacity; a hardcoded low-opacity white is what made them vanish in light mode once.

Side sheets

Slide in from the right at full height, overlaying the page rather than reflowing it, so nothing underneath shifts when a sheet opens. Glass or solid depending on solid-mode; the settings sheet is deliberately flat.

Do & don't

Do
  • Let accent and wallpaper be the only strongly personalised choices; keep spacing, radius, elevation and type fixed across installs.
  • Match the shadow step to the real stacking order.
  • Keep the clock as the one surface with a user-selectable font.
  • Use neutral elevation shadows on interactive elements — depth means layer, not brand.
  • Compute ink against the real backdrop whenever a surface is translucent.
  • Gate wallpaper text-shadow to wallpaper mode only.
  • Use tokens for radius, spacing, type and timing; a literal value needs a documented reason.
Don't
  • Introduce a second brand or accent colour.
  • Use a coloured or glowing shadow on a button or card.
  • Cluster several font sizes within a few pixels on one surface.
  • Stack a blurred panel on top of another blurred panel.
  • Ship an <img> with an empty src.
  • Re-blur a full-screen image on every view change when opacity can do the work.
